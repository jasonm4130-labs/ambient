# Plan: the session API behind the window

**Goal:** every verb the new window needs exists in Rust first, with a CLI
form and a JSON form, so the web page (next plan) is a view over functions
that are already tested.
**Architecture:** `src/api.rs` holds one dispatcher, `call(method, params, root)`,
that the MCP verb and the window bridge both route through
([ADR 0017](../adr/0017-one-web-page-for-the-window.md)). New capabilities
(search, session metadata, delete, export formats) are `session::` functions
with unit tests, then one `match` arm each in `api.rs`, then a CLI verb.
**Tech Stack:** Rust 1.85 floor, serde/serde_json, no new crates.

## Global Constraints

- This plan's branch is cut from the MCP plan's branch and lands after the session-tools and
  MCP plans (`src/mcp.rs`, `mcp::handle`, ADR 0016 and
  `session::{summaries, transcript_appended, live_session_in, undo_last_naming}` are on that
  branch, not yet on `main`). A task that finds one missing stops and reports it; it does not
  reimplement it.
- Sessions are shared with the transcriber, the window and `ambient mcp` in another process. One
  lock protects a session directory: `session::claim_transcription(dir)` (`src/session.rs:456`,
  the hard-link lock the transcriber takes for the whole of `transcribe_inner`). The protocol: the
  session functions that write (`diarize_session`, `name_speaker`, `undo_last_naming`, and this
  plan's `update_meta`, `delete`) stay lock-free themselves, because the transcriber calls
  `diarize_session` while already holding the lock; every *entry point* that calls one of them
  (each `api::call` method, each CLI arm, the window's diarize worker) claims the lock around the
  call and fails with the lock's message when a live transcriber holds it. Task 4 brings the
  existing `diarize`, `name` and `undo` CLI arms under this rule. A check followed by an unlocked
  write is not enough.
- `raw.jsonl` is never rewritten. Metadata edits rewrite `session.json` only;
  speaker edits append to `edits.jsonl`.
- Every `api::call` method has a JSON example in `docs/developing/api.md`
  (created by Task 1) and a test in `src/api.rs` that feeds that exact JSON.
- Tests use a directory unique to the test:
  `std::env::temp_dir().join(format!("ambient-{}-{}", <test fn name>, std::process::id()))`.
- `scripts/check` does not look at docs; after any docs edit run
  `node .github/scripts/check-links.mjs` and quote `… 0 broken link(s)`.
- No `.github/workflows/`, `.claude/`, or `loop/` changes; no editing existing tests.

## Task 1: One dispatcher for the window and MCP

**Files:**
- Create: `src/api.rs`; register `pub mod api;` in `src/lib.rs` before writing the test
- Modify: `src/mcp.rs` (the `tools/call` arm routes to `api::call`; the tool descriptors move to `api::methods()`)

**Interfaces:**
- Produces: `pub struct Method { pub name: &'static str, pub description: &'static str, pub input_schema: serde_json::Value }`;
  `pub fn methods() -> Vec<Method>`; `pub struct Paths { pub config_file: PathBuf, pub roster_file: PathBuf }`
  with `Paths::root(&self) -> PathBuf`, which reads `sessions_dir` from `Config::load_from(&self.config_file)`
  on every call (so a `config.set` of `sessions_dir` moves the next `sessions`/`search`/`delete`

  `pub fn call(method: &str, params: &serde_json::Value, paths: &Paths) -> Result<serde_json::Value, ApiError>`
  (the signature is fixed here; later tasks add methods, never arguments)
  with `pub enum ApiError { InvalidParams(String), Failed(String) }` (`InvalidParams` is what MCP maps to
  `-32602`, `Failed` to `isError: true`). Methods at the end of this task: `sessions`, `transcript`

  window's sake: `transcript` replies `{session, state: "live"|"transcribing"|"pending"|"done", next: <append-order line count>, lines: [Line…]}`
  and a `live` session without `raw.jsonl` yet is `state: "live"`, `lines: []`, not an error.

## Task 4: Delete a session

**Files:**
- Modify: `src/session.rs` (new `pub fn delete(root: &Path, id: &str) -> Result<()>` next to `sweep_audio_at`, `src/session.rs:992`)
- Modify: `src/api.rs` (method `session.delete` with `session` required), `docs/developing/api.md`
- Modify: `src/main.rs` (new `delete` arm: `ambient delete <dir> --yes`; the existing `diarize`, `name` and `undo` arms claim `claim_transcription(dir)` around their session call), `USAGE`; `docs/using/commands.md`; `docs/using/what-is-kept.md` (one sentence: delete removes the directory, retention only removes audio)

**Interfaces:**
- Produces: `delete(root, id, lock: &TranscribeLock)` validates the id (a single non-symlink
  directory under `root`, the MCP plan's rule) and takes proof of the lock rather than claiming it,
  so it follows the protocol above: the `api` method and the CLI arm claim `claim_transcription(dir)`
  once (a live transcriber, diarizer or namer makes that fail "is being transcribed by another
  process", and none can start while it is held) and pass the guard in. It then checks for a live
  capture: `live_session_in(root)` names this dir, or either native track
  (`audio/room.native.wav`, `audio/call.native.wav`) was modified in the last 5 s ("session is
  still recording"; a quiet microphone stops the room file growing while the call file still does).
  A directory with no `session.json` and no fresh audio on either track is a failed capture and is
  deleted like any other. Then `std::fs::remove_dir_all` while the caller still holds the lock (the
  lock file goes with the directory; `TranscribeLock::drop` tolerates a missing file). The CLI
  refuses without `--yes`.

- [ ] **Step 1:** write the failing tests: `delete` removes a finished temp session; removes a
  directory with no `session.json` and both native tracks last modified an hour ago (a failed
  capture); refuses one with a fresh `audio/room.native.wav`; refuses one whose room file is an hour
  old but whose `audio/call.native.wav` is fresh (a live call with a quiet room); the `api` method
  against a session whose `transcribing.lock` names this test's pid errors "being transcribed" and
  leaves the directory intact, and against a finished session succeeds (one claim, no self-conflict); refuses `"../x"`; refuses a symlinked entry; the CLI arm without
  `--yes` prints "add --yes" and exits non-zero (test the pure argument check as a function).
- [ ] **Step 2:** run `cargo test session::delete`, expect FAIL "cannot find function".
- [ ] **Step 3:** implement, add the `api` method (the window shows its own confirm dialog; the API
  does not ask) and the CLI verb.
- [ ] **Step 4:** run `scripts/check`, expect `CHECK OK`; `node .github/scripts/check-links.mjs`,
  expect `0 broken link(s)`.
- [ ] **Step 5:** commit: `git add src/session.rs src/api.rs src/main.rs docs/developing/api.md docs/using/commands.md docs/using/what-is-kept.md && git commit -m "delete: remove a session, never a live one; writers take the lock"`.
