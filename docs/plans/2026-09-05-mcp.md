# Plan: reading sessions over MCP

**Goal:** let another program read Ambient's sessions, including the one being
recorded, through `ambient mcp`, per [ADR 0016](../adr/0016-mcp-verb-for-live-reading.md).
**Architecture:** `src/mcp.rs` holds a synchronous JSON-RPC 2.0 loop over
newline-delimited stdio with a `serve(reader, writer, root)` entry point that
tests drive with in-memory buffers. Tools call the same `session` functions the
CLI verbs call. `src/main.rs` gains the `mcp` arm.
**Tech Stack:** Rust 1.85 floor, serde_json only; no async runtime, no MCP SDK.

## Global Constraints

- Wire format: one JSON-RPC 2.0 message per line, UTF-8, `\n` terminated; nothing else on stdout.
  Diagnostics go to stderr. The loop never panics on input: every handler returns a `Result` and an
  `Err` becomes a JSON-RPC error response.
- Protocol version: reply with the client's `protocolVersion` when it is one of
  `2025-11-25`, `2025-06-18`, `2025-03-26`; otherwise reply `2025-11-25`, the latest this server
  supports, which is what the lifecycle spec requires for an unsupported request. The 2026-07-28
  revision retired the `initialize` handshake and is not claimed.
- Error classes: a line that is not JSON → `-32700`; an object without `"jsonrpc":"2.0"` or a
  non-string `method` → `-32600`; an unknown method → `-32601`; `tools/call` with missing or non-object
  `params`/`arguments`, a non-string `name`, an unknown tool name, or an argument of the wrong type →
  `-32602`; a tool that ran and failed (no such session, unreadable file) → a result with
  `isError: true` and the message as text.
- Every tool result is `{"content":[{"type":"text","text":"<JSON>"}],"isError":false}` where the text
  is the tool's JSON value serialised compactly.
- A session id must be a non-empty single path segment (no `/`, not `.` or `..`), and `root.join(id)`
  must be a directory by `symlink_metadata` (a symlink is refused); otherwise the tool errors, and no
  path outside the root is ever read. Enumeration obeys the same rule: one private
  `fn session_dirs(root) -> Vec<PathBuf>` in `src/mcp.rs` walks the root, keeps entries whose
  `symlink_metadata` is a directory, and keeps those holding a `session.json` or a growing
  `audio/room.native.wav`; both `sessions` and `status.sessions` use it, so they always agree
  (`session::list` follows symlinks, which is why the walk lives here). The files inside a session
  are checked the same way: before `raw.jsonl`, `edits.jsonl` or `session.json` is read, its
  `symlink_metadata` must be a regular file, else the tool errors with `refusing symlink <path>`
  (for `sessions`, that session is listed with `error` set and metadata `None`).
- This plan lands after the session-tools plan. Where a task consumes `session::summaries`,
  `session::live_session_in` or `Line: Serialize`, and they are not on `main`, the task adds them
  exactly as specified in its Interfaces before proceeding.
- `scripts/check` does not look at docs. After any docs edit run
  `node .github/scripts/check-links.mjs` and quote its `… 0 broken link(s)` line.
- No `.github/workflows/`, `.claude/`, or `loop/` changes; no editing existing tests.

## Task 2: The `sessions` and `transcript` tools

**Files:**
- Modify: `src/mcp.rs` (implement the two tools)
- Modify: `src/session.rs` (new `pub fn transcript_appended(dir: &Path, verbatim: bool) -> Result<Vec<Line>>`
  next to `transcript` at `src/session.rs:1059`; and `summaries` or `Line: Serialize` if missing, see Interfaces)

**Interfaces:**
- Consumes: `session::summaries(root: &Path) -> Vec<SessionSummary>` where
  `#[derive(Serialize)] pub struct SessionSummary { pub id: String, pub dir: PathBuf, pub name: Option<String>, pub started_at: Option<String>, pub duration_s: Option<f64>, pub transcribed: bool, pub live: bool, pub transcribing: bool, pub error: Option<String> }`
  (newest first; a dir is included when it holds `session.json` or a growing `audio/room.native.wav`,
  since capture writes `session.json` only after the scratch wavs close; an unparsable
  `session.json` is included with `error` set); `#[derive(Serialize)]` on `Line { track, start_ms, end_ms, speaker, text }`;
  `session::is_growing`, `session::live_transcriber`. Add any that is absent.
- Produces in `src/session.rs`: `transcript_appended(dir, verbatim)`, the same fold over `raw.jsonl`
  and `edits.jsonl` as `transcript` but returning lines in `raw.jsonl` order, without the
  `sort_by_key(start_ms)` at `src/session.rs:1123`; refactor so both share one body with a `sort: bool`
  argument in a private helper, so they cannot drift. Test in `src/session.rs`: `raw.jsonl` holding a
  `room` line at 5000 then a `call` line at 0 → `transcript` returns `[0, 5000]` by `start_ms`,
  `transcript_appended` returns `[5000, 0]`.
- Produces: tool `sessions` (no arguments) → the JSON array of summaries; tool `transcript` with
  `{"session": "<id>", "since": <u64, optional, default 0>, "verbatim": <bool, optional, default false>}`
  → `{"session": "<id>", "state": "<live|transcribing|pending|done>", "next": <u64>, "lines": [<Line>…]}`.
  `since` is a count of lines already seen in append order (the order `transcript_appended` returns),
  `lines` is every line from index `since` on, and `next` is the total line count, the value to pass
  back as `since`. The cursor is append
  order and not a timestamp because `raw.jsonl` is written room track first, then call track
  (`src/session.rs:852`), and the two tracks' `start_ms` clocks are independent, so a time cursor
  would skip call lines appended after room lines. `state` is `live` while `audio/room.native.wav` is growing,
  `transcribing` while `live_transcriber` names a live pid, `done` when `transcript.md` exists, and
  `pending` otherwise (captured, waiting for the queue). When `raw.jsonl` is absent, `lines` is empty
  and the call succeeds; a `raw.jsonl` that exists but does not parse is `isError: true`.

- [ ] **Step 1:** write the failing tests: temp root with session `2026-09-05-1200` holding
  `session.json`, `raw.jsonl` (two lines, `start_ms` 0 and 5000) and `transcript.md`:
  `sessions` → one summary with `id == "2026-09-05-1200"`, `transcribed == true`;
  `transcript` with `since: 1` → one line with `start_ms == 5000`, `next == 2`, `state == "done"`;
  `transcript` with `since: 2` → no lines, `next == 2`; `transcript` with `since: 9` → no lines, `next == 2`;
  the append-order race: `raw.jsonl` holding a `room` line at 5000 then a `call` line at 0, `since: 1`
  → the `call` line at 0 is returned (a time cursor would have lost it);
  `transcript` with `{"session":"2026-09-05-1200","since":"1"}` → `error.code == -32602`;
  `transcript` with `session: "../x"`, `session: ""`, `session: "."` → `isError: true` each;
  `transcript` with `session: "nope"` → `isError: true` and text containing `no session nope`;
  a symlink `link -> 2026-09-05-1200` in the root, `session: "link"` → `isError: true`, and `sessions`
  does not list `link`; a symlink `outside` pointing at a temp directory outside the root holding a
  `session.json` → `sessions` does not list it either; a real dir `leak` whose `raw.jsonl` is a symlink
  to a file outside the root → `transcript` on `leak` is `isError: true` with text containing
  `refusing symlink`, and `sessions` lists `leak` with `error` set;
  a second dir with `session.json` and a fresh `audio/room.native.wav` (written in the test so its
  mtime is now) and no `raw.jsonl` → `state == "live"`, `lines == []`;
  a third dir with `session.json` only → `state == "pending"`, `lines == []`.
