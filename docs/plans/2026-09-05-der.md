# Plan: who spoke

**Goal:** measure how often Ambient's diarizer assigns speech to the wrong
speaker, on a public meeting corpus, with the same `Diarizer::diarize` call
`ambient diarize` makes; then tune the diarizer against that number.
**Architecture:** a diarization error rate (DER) scorer in `src/der.rs`, an
AMI fixture fetched into `~/.cache/ambient`, a harness binary that runs
`Diarizer::diarize` over the fixture and scores it, a `der=` figure on the
quality script's last line, then one experiment per task with a keep-or-restore
rule.
**Tech Stack:** Rust 1.85 floor, no new crates (anyhow, serde_json, hound only);
bash + ffmpeg + curl + shasum for the fixture; ONNX models already in `models/`.

## Global Constraints

- The number is span-level DER: how the diarizer's spans compare with the
  reference turns. The later step in `session::diarize_session` that gives each
  `raw.jsonl` record its majority speaker (`src/session.rs:1241`) is not scored
  here; a record straddling two turns is a transcript-level error and gets its
  own plan once `raw.jsonl`-level fixtures exist.
- The fixture is AMI Mix-Headset audio (CC BY 4.0) with the pyannote
  `only_words` RTTM references pinned to commit
  `67c2d539286e89f68952d5dcf83912bd9f01dfae`. Cached under
  `~/.cache/ambient/fixtures/der/`, never committed.
- The number is DER with a 0.25 s collar as `cargo run --release --bin der`
  prints it in its total row. Report it in the pull request body.
- An experiment that makes the number worse reverts its code change before the
  task ends and records the table in `docs/developing/measurements.md`.
- `scripts/check` does not look at docs. After any docs edit run
  `node .github/scripts/check-links.mjs` and quote its `… 0 broken link(s)` line.
- Nothing here touches capture, the menu bar, the settings UI, or `src/asr.rs`.
- No `.github/workflows/`, `.claude/`, or `loop/` changes; no editing existing tests.

## Task 1: A DER scorer with tests

**Files:**
- Create: `src/der.rs`
- Modify: `src/lib.rs` (add `pub mod der;` in alphabetical position, before writing any test)

**Interfaces:**
- Produces: `pub struct Turn { pub start_s: f64, pub end_s: f64, pub speaker: String }`;
  `pub fn parse_rttm(text: &str) -> anyhow::Result<Vec<Turn>>`;
  `pub struct Der { pub missed_s: f64, pub false_alarm_s: f64, pub confusion_s: f64, pub reference_s: f64 }`
  with `pub fn rate(&self) -> f64` = `(missed + false_alarm + confusion) / reference`;
  `pub fn score(reference: &[Turn], hypothesis: &[Turn], collar_s: f64) -> anyhow::Result<Der>`,
  an error only when the reference is empty (`empty reference`); any number of speakers on either
  side is scored, so an over-clustered candidate in a sweep gets a number, not an abort.

- [ ] **Step 1:** add `pub mod der;` to `src/lib.rs`, create `src/der.rs` holding only the
  `#[cfg(test)] mod tests` below (every test passes `collar_s` 0.0 except the collar test), and run
  `cargo test der::` once to see the red:
  - `parse_rttm` on `SPEAKER ES2004a 1 12.34 5.00 <NA> <NA> FEE013 <NA> <NA>` yields
    `Turn{start_s:12.34,end_s:17.34,speaker:"FEE013"}`; blank lines and lines starting with `;;` are
    skipped; any other line not starting with `SPEAKER`, or with fewer than 8 fields, is an error naming
    the line number (an HTML error page saved as an RTTM must fail, not parse to nothing).
  - identical reference and hypothesis score `rate() == 0.0`.
  - reference `A 0–10`, hypothesis empty: `missed_s == 10.0`.
  - reference empty, hypothesis `A 0–4`: `score` is an error containing `empty reference`.
  - reference `A 0–10, B 10–20`, hypothesis `X 0–10, Y 10–20`: rate 0.0 (labels are mapped, not compared).
  - reference `A 0–10, B 10–20`, hypothesis `X 0–20`: `confusion_s == 10.0` (within 0.05).
  - over-clustering: reference `A 0–17, B 17–25`, hypothesis `X 0–9, Y 9–17, X 17–25`: the optimal
    map is A→Y, B→X (16 s correct, `confusion_s == 9.0` within 0.05); a greedy assignment takes A→X
    first (9 s) and leaves B nothing, scoring 16 s of confusion, so this test fails on greedy.
  - many clusters: reference `A 0–10, B 10–20`, hypothesis with twelve labels `H0..H11`, label `Hi`
    covering `[i, i+1)`: `score` is `Ok`; one label maps to A and one to B (2 s correct), so
    `confusion_s == 10.0`, `missed_s == 8.0` (12–20 has no hypothesis), `false_alarm_s == 0.0`.
  - collar: reference `A 0–10`, hypothesis `A 0.2–10`, collar 0.25: rate 0.0; collar 0.0: `missed_s ≈ 0.2`.
- [ ] **Step 2:** expect FAIL with "cannot find function" for each item.
- [ ] **Step 3:** implement. Discretise both sides into 10 ms frames over `max(end)` of both. A frame is
  excluded when it lies within `collar_s` of any reference turn boundary. Per frame collect the set of
  reference speakers and hypothesis speakers. Speaker mapping is exact for any count: build the
  overlap matrix (reference × hypothesis, in included frames), pad it to square with zeros, and solve
  the maximum-weight assignment with the Hungarian algorithm (O(n³), about sixty lines, written in
  `src/der.rs` with a comment naming it; no crate). Then per included frame, with `n_ref` the number of
  reference speakers, `n_hyp` the number of hypothesis speakers, and `n_correct` the reference
  speakers whose mapped hypothesis label is present: missed = `max(n_ref − n_hyp, 0)`, false alarm =
  `max(n_hyp − n_ref, 0)`, confusion = `min(n_ref, n_hyp) − n_correct`, each × 0.01 s (the NIST
  md-eval cardinality formula, so an unmapped label speaking over a reference speaker is confusion,
  not a miss plus a false alarm). `reference_s` = sum of `n_ref` × 0.01 s over included frames.
  Comment the frame size.
- [ ] **Step 4:** run `scripts/check`, expect last line `CHECK OK`.
- [ ] **Step 5:** commit: `git add src/der.rs src/lib.rs && git commit -m "der: diarization error rate scorer"`.
